## BUG #1 — mouse invertido (RESOLVIDO 2026-11-25)
Fix: `player.js` yaw `-=` → `+=` (convenção FPS: yaw cresce → vista roda à direita);
`input.js`: `pointerlockchange` zera deltas acumulados + filtro |movement|>200px/evento.
Verificação (tools/probe-mouse.mjs, headless, deltas sintéticos):
  yaw após 12×10px à direita = +2.6322 (inicial 2.3562; Δ = +0.276 = 12·10·0.0023 exato) ✓
  yaw após 12×-10px        = +2.3562 (simétrico) ✓
  spike movementX=500      → ignorado (yaw inalterado) ✓
  rato p/ baixo            → pitch desce (convenção mantida) ✓
Caveat: pointer lock real só no hardware do user; headless simulou lock+eventos.
## BUG ABERTO #1 (prioridade do user) — mouse invertido no eixo X + "estalo"
Evidências (código):
- `input.js`: `mousemove` acumula `e.movementX/Y` sem filtro de picos; sem valor no
  `pointerlockchange` → deltas acumulam através da transição de lock.
- `player.js`: `this.yaw -= md.x * sensitivity` com `fwd=[sin yaw,0,-cos yaw]`.
  Consequência: rato para a direita ⇒ yaw decresce ⇒ vista roda para −X (esquerda).
  Horizontal invertido — confirma a queixa do user (vertical está ok).
Causa raiz: sinal do yaw invertido + ausência de spike-guard de pointer lock.
Correção: `yaw += md.x * sensitivity` + `pointerlockchange` reseta deltas + filtro
|movement|>200px/evento ignorado.
